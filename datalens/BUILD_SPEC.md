# Спек сборки дашборда в DataLens

Этот документ — **пошаговая инструкция** для ручной сборки showcase-дашборда
в Yandex DataLens UI. Одноразовая операция: собрал по спеку → экспортнул
воркбук → закоммитил `datalens/dashboard.json` → все последующие пользователи
импортят экспорт без модификаций.

> **Почему нельзя сгенерить JSON автоматом.** Экспорт-файл содержит `hash`
> (HMAC, подписанный серверным секретом `exportDataVerificationKey`). На импорте
> сервер проверяет подпись. Любой handcrafted/edited JSON → импорт падает.
> Единственный валидный путь — собрать в UI и экспортнуть. См.
> [datalens-meta-manager/workbook-import](https://github.com/datalens-tech/datalens-meta-manager/blob/main/src/controllers/workbook-import/start-workbook-import/index.ts).

---

## 0. Предусловия

Прогон `terraform apply` должен быть выполнен, и в кластере должны быть
данные (после первого запуска `scripts/smoke.sh`). Нужны значения из
`terraform output`:

```bash
terraform -chdir=terraform output clickhouse_cluster_id  # c9q...
terraform -chdir=terraform output clickhouse_db_name     # metrika
terraform -chdir=terraform output clickhouse_db_user     # analyst
```

На кластере уже включено `access.data_lens = true` — в выпадашке DataLens
кластер появится без дополнительных настроек со стороны MDB.

---

## 1. Коллекция и воркбук

1. Открой https://datalens.yandex.cloud → **Коллекции** → **Создать коллекцию**
   → имя: `Атрибуция Метрики`.
2. Внутри коллекции → **Создать воркбук** → имя: `Дашборд атрибуции`.

Все следующие объекты создаются внутри воркбука — так они одним
файлом уедут в `dashboard.json` при экспорте.

## 2. Подключение (единственный ручной шаг для конечного пользователя)

Внутри воркбука → **Добавить** → **Подключение** → **Managed Service for ClickHouse**.

| Поле | Значение |
|------|----------|
| Кластер | выбери из списка по `clickhouse_cluster_id` |
| Имя пользователя | `analyst` (значение `clickhouse_db_user`) |
| Пароль | пароль ClickHouse (тот же, что в Lockbox) |
| Уровень SQL-запросов | **Подзапросы** (нужно для датасета `ds_chains`) |
| Время жизни кэша, с | `300` (5 минут — дашборд интерактивный) |

Имя подключения: `ch_metrika`.

> При импорте готового воркбука этот же шаг выполнит конечный пользователь:
> DataLens попросит «привязать подключение» и покажет список его кластеров.

## 3. Датасет #1: `ds_attribution` (основной)

**Источник:** таблица `attribution_results`.

### Поля источника

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Модель атрибуции | `attribution_type` | Строка | Нет | Измерение |
| Дата | `start_date` | Дата | Нет | Измерение |
| Источник атрибуции | `source_code` | Строка | Нет | Измерение |
| Число визитов | `visits` | Дробное число | Сумма | Показатель |
| Число конверсий | `conversions` | Дробное число | Сумма | Показатель |
| Доход | `revenue` | Дробное число | Сумма | Показатель |

### Вычисляемые поля (формулы)

| Название | Формула | Тип | Роль |
|----------|---------|-----|------|
| Конверсия, % | `[Число конверсий] / [Число визитов]` | Дробное число | Показатель |
| Доход на визит | `[Доход] / [Число визитов]` | Дробное число | Показатель |
| Доход на конверсию | `[Доход] / [Число конверсий]` | Дробное число | Показатель |
| Название модели атрибуции | см. ниже | Строка | Измерение |
| Название источника атрибуции | см. ниже | Строка | Измерение |

**Название модели атрибуции:**

```
CASE [Модель атрибуции]
  WHEN 'first_touch' THEN 'Первый клик'
  WHEN 'last_touch' THEN 'Последний клик'
  WHEN 'linear' THEN 'Линейная'
  WHEN 'time_decay' THEN 'Затухающая'
END
```

**Название источника атрибуции:**

Для 1-к-1 соответствий (`-1`, `0`, `1`, `4`-`7`, `11`) выдаём человекочитаемое
имя. Для префиксных семейств (`2_*`, `3_*`, `8_*`, `9_*`, `10_*`) несколько
разных id попали бы в одну строку (`2_621` Яндекс vs `2_1` Google — оба
«Поиск»). Пока у нас нет словаря поисковиков/рекламных систем/соцсетей,
оставляем оригинальный id в скобках, чтобы пользователь видел разницу.

```
CASE [Источник атрибуции]
  WHEN '-1' THEN 'Внутренние переходы'
  WHEN '0'  THEN 'Прямые заходы'
  WHEN '1'  THEN 'Переходы с сайтов'
  WHEN '4'  THEN 'Сохраненные страницы'
  WHEN '5'  THEN 'Не определено'
  WHEN '6'  THEN 'Внешние переходы'
  WHEN '7'  THEN 'E-mail'
  WHEN '11' THEN 'QR коды'
  ELSE
    CASE SUBSTR([Источник атрибуции], 1, 2)
      WHEN '2_' THEN CONCAT('Поиск (', [Источник атрибуции], ')')
      WHEN '3_' THEN CONCAT('Реклама (', [Источник атрибуции], ')')
      WHEN '8_' THEN CONCAT('Социальные сети (', [Источник атрибуции], ')')
      WHEN '9_' THEN CONCAT('Рекомендательные системы (', [Источник атрибуции], ')')
      WHEN '10' THEN CONCAT('Мессенджеры (', [Источник атрибуции], ')')
      ELSE [Источник атрибуции]
    END
END
```

> В v2 заменим скобки на настоящие имена, взятые **из самих данных**
> (не из хардкод-таблицы). В `TrafficSource` Метрики у каждого числового
> `*ID` есть строковая пара `*StrID`: `SearchEngineID` ↔ `SearchEngineStrID`,
> `AdvEngineID` ↔ `AdvEngineStrID`, `SocialSourceNetworkID` ↔ `SocialSourceNetworkStrID`,
> `RecommendationSystemID` ↔ `RecommendationSystemStrID`, `MessengerID` ↔ `MessengerStrID`.
> Любой хардкод-словарь (включая таблицу в `README.md` — она заведомо
> неточная и, возможно, местами просто неверная) проигрывает этому источнику.
> План v2: расширить схемы `visits_prepared` / `visits_combined` колонками
> `*StrID`, протащить их до `attribution_results`, и тут в DataLens
> формировать имя по реальной паре id→str без хардкода.

### Фильтры на уровне датасета — не задаём

Диапазон дат не фиксируем на уровне датасета: пользователь должен сам
выбирать период в глобальном селекторе **Период** (см. §7) и сравнивать
разные отрезки. Перфоманс-защита — «последние 30 дней» как значение по
умолчанию в самом селекторе, плюс per-chart фильтр у `ch_time_series`
(у него свой диапазон — 90 дней). Этого хватит, чтобы чарты не скейнили
всю историю на первом рендере, а у пользователя осталась свобода.

## 4. Датасет #2: `ds_chains` (для Sankey)

**Источник:** SQL-подзапрос (в подключении нужно
«Уровень SQL-запросов = Подзапросы»).

Сам запрос агрегирует парные переходы между позициями в цепочке:

```sql
SELECT
    history.SourceCode[i]   AS from_channel,
    history.SourceCode[i+1] AS to_channel,
    i                       AS step,
    count()                 AS visits,
    sum(Conversions)        AS conversions
FROM (
    SELECT
        history.SourceCode,
        Conversions,
        arrayJoin(range(1, length(history.SourceCode))) AS i
    FROM metrika.visits_combined
    WHERE length(history.SourceCode) >= 2
) AS expanded
GROUP BY from_channel, to_channel, step
HAVING visits >= 5
ORDER BY step, visits DESC
```

> `arrayJoin(range(1, length(...)))` в ClickHouse даёт индексы `1..length-1`,
> что гарантирует валидный `history.SourceCode[i+1]` для всех строк.
> Массивы в CH 1-индексные, так что `[i]` начинается с первого касания.
> Если захочется показать только цепочки с конверсией — добавь
> `WHERE ... AND Conversions > 0` во внутренний SELECT.

### Поля

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Откуда | `from_channel` | Строка | Нет | Измерение |
| Куда | `to_channel` | Строка | Нет | Измерение |
| Шаг | `step` | Целое число | Нет | Измерение |
| Визиты цепочки | `visits` | Целое число | Сумма | Показатель |
| Конверсии цепочки | `conversions` | Дробное число | Сумма | Показатель |

## 6. Чарты (8 штук)

### Чарт 1 — `kpi_revenue`: KPI «Атрибутированный доход» (30д, Линейная)

- Тип: **Индикатор**
- Датасет: `ds_attribution`
- Показатель: `Доход`
- Фильтры: `Название модели атрибуции = Линейная`
- Подзаголовок: «Атрибутированный доход · Линейная»
- Формат: `₽`, разделитель тысяч, без дробной части

> Период тут НЕ фиксируем фильтром чарта — он управляется глобальным
> селектором «Период» (default: последние 30 дней). Так пользователь
> может произвольно менять диапазон и сравнивать сам.

> **WoW-дельта внутри Индикатора в DataLens нативно недоступна.**
> Если очень нужно — вынеси её в v2 одним из путей:
> (а) дублировать чарт со сдвинутым per-chart фильтром и положить рядом,
> (б) calc-field-дельта в датасете (`SUM(IF([Дата] BETWEEN TODAY()-60 AND TODAY()-30, [Доход], 0))` и т.д.) —
> но тогда глобальный селектор «Период» на эти KPI работать не будет.

### Чарт 2 — `kpi_conversions`: KPI «Атрибутированные конверсии»

- Тип: **Индикатор**
- Показатель: `Число конверсий`
- Фильтры: `Название модели атрибуции = Линейная`
- Подзаголовок: «Конверсии · Линейная»
- Формат: целое число, разделитель тысяч

### Чарт 3 — `kpi_touchpoints`: KPI «Среднее число касаний до конверсии»

- **Этот KPI строится на отдельном датасете** — нужно значение из
  `visits_combined` напрямую. Создай третий датасет `ds_touchpoints`
  подзапросом (Уровень SQL-запросов = Подзапросы):

  ```sql
  SELECT
      toDate(history.UTCStartTime[-1]) AS conversion_date,
      length(history.SourceCode)       AS touchpoints
  FROM metrika.visits_combined
  WHERE Conversions > 0
  ```

  Поля датасета:

  | Название | Источник | Тип | Агрегация | Роль |
  |----------|----------|-----|-----------|------|
  | Дата конверсии | `conversion_date` | Дата | Нет | Измерение |
  | Число касаний | `touchpoints` | Целое число | **Среднее** | Показатель |

  > Фильтр по дате в SQL **не зашиваем**. Период управляется глобальным
  > селектором «Период» на дашборде (см. §7) — он привязывается к
  > `Дата конверсии` для этого чарта. Запрос отдаёт строку на каждый
  > конвертирующий визит; ClickHouse и DataLens спокойно проагрегируют.

- Тип: **Индикатор**; показатель: `Число касаний`; формат: `0.0`
- Подзаголовок: «Среднее число касаний до конверсии»

### Чарт 4 — `ch_model_mix`: распределение источников по моделям (100% стек)

- Тип: **Столбчатая диаграмма нормированная** (100% stacked)
- Датасет: `ds_attribution`
- X: `Название модели атрибуции`
- Y: `Число конверсий`
- Цвета: `Название источника атрибуции`
- Сортировка: `Число конверсий` по убыванию (чтобы топовые источники
  оказались сверху легенды)
- Ограничение: в настройках чарта → «Количество элементов» = `5`
  (оставляем топ-5 источников; остальные скрываются)
- Фильтры: **только дата через глобальный селектор «Период»** (§7);
  своих фильтров у чарта нет
- Название: «Распределение источников по моделям атрибуции»
- Подзаголовок: «Как по-разному модели атрибутируют каналы»

> В DataLens нет отдельного «Топ-фильтра» — ограничение делается через
> «Сортировку + Количество элементов». Если нужен строгий «топ по
> конкретной модели» — создай вычисляемое измерение
> `Ранг источника = RANK_DENSE(SUM([Число конверсий]) AMONG [Название источника атрибуции])`
> и наложи фильтр `Ранг источника <= 5`. Для showcase'а это избыточно.

### Чарт 5 — `ch_time_series`: ежедневные конверсии по моделям

- Тип: **Линейная диаграмма**
- Датасет: `ds_attribution`
- X: `Дата`
- Y: `Число конверсий`
- Цвета: `Название модели атрибуции` (ручная палитра из §5)
- Фильтры: нет. Диапазон задаётся глобальным селектором «Период»
  (default: последние 30 дней).
- Название: «Атрибутированные конверсии во времени»
- Подзаголовок: «Все 4 модели, ежедневно»
- Ось Y: линейная (без логарифмической шкалы)
- Сглаживание: выкл (показываем реальные дневные колебания)

### Чарт 6 — `ch_channel_grouped`: топ-10 источников × 4 модели

- Тип: **Столбчатая диаграмма** (группированные столбцы)
- Датасет: `ds_attribution`
- X: `Название источника атрибуции`
- Y: `Число конверсий`
- Цвета: `Название модели атрибуции` (ручная палитра из §5)
- Сортировка: `Число конверсий` по убыванию
- Ограничение: в настройках чарта → «Количество элементов» = `10`
- Фильтры: **только дата через глобальный селектор «Период»** (§7)
- Название: «Топ источников: расхождения между моделями»

### Чарт 7 — `ch_sankey`: Sankey цепочек касаний (Чарт-редактор)

В Wizard'е Sankey **нет** — делаем через **Чарт-редактор** (custom JS).

1. Воркбук → **Добавить** → **Чарт-редактор** → шаблон: **Custom JS**.
2. Привязанный датасет: `ds_chains`.
3. Вкладки (tabs) с кодом:

Вкладка **`params`**:

```json
{
  "chart_name": "Touch chains sankey",
  "max_steps": 3
}
```

Вкладка **`url`** — оставь пустой (данные читаем через `Editor.getLoadedData()`).

Вкладка **`js`**:

```js
// Source: ds_chains grouped by (from_channel, to_channel, step)
const data = Editor.getLoadedData();
const rows = data?.[0]?.rows ?? [];
const maxStep = 3;  // показываем 3 перехода максимум

const nodes = new Map();  // "step:channel" -> index
const links = [];

function nodeId(step, ch) {
    const k = `${step}:${ch}`;
    if (!nodes.has(k)) nodes.set(k, { id: nodes.size, name: ch, step });
    return nodes.get(k).id;
}

for (const row of rows) {
    const [from, to, step, visits] = row;
    if (step > maxStep) continue;
    links.push({
        source: nodeId(step, from),
        target: nodeId(step + 1, to),
        value: Number(visits),
    });
}

module.exports = {
    data: {
        nodes: [...nodes.values()],
        links,
    },
};
```

Вкладка **`ui`**:

```json
{
  "controls": []
}
```

Вкладка **`graph`** (конфиг чарта, передаётся в d3-sankey-рендер):

```json
{
  "chart": { "type": "sankey" },
  "series": [{
    "type": "sankey",
    "data": "{{data}}",
    "nodeAlign": "left",
    "nodeWidth": 12,
    "nodePadding": 8
  }],
  "tooltip": { "enabled": true }
}
```

Вкладка **`shared`** — оставь пустой (между вкладками состояние не передаётся).

> Если Чарт-редактор не рендерит sankey «из коробки», запасной путь —
> подтянуть публичный `d3-sankey` через CDN во вкладке **`js`**:
>
> ```js
> const d3 = require('https://cdn.jsdelivr.net/npm/d3@7/+esm');
> const d3sankey = require('https://cdn.jsdelivr.net/npm/d3-sankey@0.12/+esm');
> // …собрать SVG вручную и вернуть через module.exports.html
> ```
>
> Сработает только если DataLens-рантайм разрешает external modules.
> Если нет — оставь чарт заглушкой с пометкой «будет в v2», не застревай.

- Название: «Путь клиента: источник → источник»
- Подзаголовок: «Топ переходов между касаниями, 30д (мин 5 визитов)»

### Чарт 8 — `ch_pivot`: сводная таблица по источникам и моделям

- Тип: **Сводная таблица**
- Датасет: `ds_attribution`
- Строки: `Название источника атрибуции`
- Столбцы: `Название модели атрибуции`
- Показатели: `Число визитов`, `Число конверсий`, `Доход`, `Доход на конверсию`
  (4 метрики в ячейке)
- Фильтры: `Дата = последние 30 дней`
- Итоги: по строкам и по столбцам — включены
- Условное форматирование: цветовая заливка по `Число конверсий` внутри столбца
- Название: «Источник × модель: все метрики»

## 7. Раскладка дашборда

Создай дашборд внутри воркбука, название: `Атрибуция Метрики — Showcase`.

**Сетка 24 колонки, высота строки = 4 юнита.**

| Ряд | Чарты | Раскладка (x, y, w, h) |
|-----|-------|------------------------|
| 1 (KPI) | `kpi_revenue`, `kpi_conversions`, `kpi_touchpoints` | (0,0,8,4) (8,0,8,4) (16,0,8,4) |
| 2 | `ch_model_mix` (слева), `ch_time_series` (справа) | (0,4,12,8) (12,4,12,8) |
| 3 | `ch_channel_grouped` (во всю ширину) | (0,12,24,8) |
| 4 | `ch_sankey` (во всю ширину) | (0,20,24,10) |
| 5 | `ch_pivot` (во всю ширину) | (0,30,24,12) |

**Глобальные селекторы** (в верхней части дашборда, над KPI-рядом):

1. **Период** — значение по умолчанию: «последние 30 дней».
   Привязка к чартам по полю даты:
   - все `ds_attribution`-чарты (`kpi_revenue`, `kpi_conversions`,
     `ch_model_mix`, `ch_time_series`, `ch_channel_grouped`, `ch_pivot`)
     → поле `Дата`
   - `kpi_touchpoints` (датасет `ds_touchpoints`) → поле `Дата конверсии`
   - **Не связывать** с `ch_sankey` — в датасете `ds_chains` даты нет
2. **Модель** — один вариант, поле датасета: `Название модели атрибуции`,
   значение по умолчанию: `Линейная`. Связать с `kpi_revenue`, `kpi_conversions`,
   `ch_pivot`, `ch_channel_grouped`. **Не связывать** с `ch_model_mix` и
   `ch_time_series` (они всегда показывают все 4 модели).
3. **Источник** — несколько вариантов, поле датасета:
   `Название источника атрибуции`. Связать со всеми чартами **кроме** `ch_sankey`
   (у него свой датасет с полями `Откуда`/`Куда`).

## 8. Экспорт и коммит

1. В воркбуке → меню **⋯** → **Экспортировать**.
2. Скачанный файл положи как `datalens/dashboard.json` в корне репо.
3. Коммить:
   ```bash
   git add datalens/dashboard.json
   git commit -m "datalens: add exported dashboard.json"
   ```

## 9. Проверка: импорт в другой каталог

Чтобы убедиться, что воркбук портируем, создай второй каталог (folder)
или используй прод-окружение:

1. Прогони `terraform apply` в новом каталоге (получишь другой
   `clickhouse_cluster_id`).
2. Открой `terraform output datalens_import_url` и перейди по ссылке.
3. **Импортировать воркбук** → выбери `datalens/dashboard.json`.
4. На шаге привязки подключения — выбери новый кластер из списка.
5. Открой дашборд — все чарты должны работать без ошибок.

Если хоть один чарт красный — импорт сломан, заводим issue.
