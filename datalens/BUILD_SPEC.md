# Сборка дашборда в DataLens

Пошаговый рецепт, по которому собран `datalens/dashboard.json`.
Выполняется один раз при правках воркбука: собрал в UI → экспортнул
→ закоммитил.

Контекст и обоснования решений — в [`NOTES.md`](NOTES.md).

---

## 0. Предусловия

`terraform apply` выполнен, в кластере есть данные (после `scripts/smoke.sh`).
Значения из `terraform output`:

```bash
terraform -chdir=terraform output clickhouse_cluster_id  # c9q...
terraform -chdir=terraform output clickhouse_db_name     # metrika
terraform -chdir=terraform output clickhouse_db_user     # analyst
```

Флаг `access.data_lens = true` на кластере — уже выставлен Terraform'ом.

## 3. Датасет `ds_attribution`

**Источник:** представление `v_attribution_results` (см. `sql/01_schema.sql`).

Именно **view**, а не таблица `attribution_results`: view резолвит
`source_code` → `source_name` через JOIN'ы к словарям `dict_*`
(заполняются из `dicts/*.csv`).  DataLens получает готовые русские
имена без CASE и без собственного словаря.

### Поля источника

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Модель атрибуции | `attribution_type` | Строка | Нет | Измерение |
| Дата | `start_date` | Дата | Нет | Измерение |
| Источник атрибуции (код) | `source_code` | Строка | Нет | Измерение |
| Название источника атрибуции | `source_name` | Строка | Нет | Измерение |
| Число визитов | `visits` | Дробное число | Сумма | Показатель |
| Число конверсий | `conversions` | Дробное число | Сумма | Показатель |
| Доход | `revenue` | Дробное число | Сумма | Показатель |

> Колонки `assisted_conversions` / `assisted_revenue` физически
> присутствуют в `v_attribution_results`, но для чартов по
> ассоциированным конверсиям используется отдельный датасет
> `ds_assisted` на view `v_assisted_long` (см. §5.6) — там данные
> уже в long-формате и строятся без фильтров-заглушек.  В
> `ds_attribution` эти поля можно не добавлять.

### Вычисляемые поля

| Название | Формула | Тип | Роль |
|----------|---------|-----|------|
| Конверсия, % | `[Число конверсий] / [Число визитов]` | Дробное число | Показатель |
| Доход на визит | `[Доход] / [Число визитов]` | Дробное число | Показатель |
| Доход на конверсию | `[Доход] / [Число конверсий]` | Дробное число | Показатель |
| Ранг источника | `RANK_DENSE(SUM([Число конверсий]) AMONG [Название источника атрибуции])` | Целое число | Показатель |
| Название модели атрибуции | формула ниже | Строка | Измерение |

**Название модели атрибуции:**

```
CASE [Модель атрибуции]
  WHEN 'first_touch'      THEN 'Первый клик'
  WHEN 'last_touch'       THEN 'Последний клик'
  WHEN 'last_significant' THEN 'Последний значимый клик'
  WHEN 'linear'           THEN 'Линейная'
  WHEN 'time_decay'       THEN 'Затухающая'
END
```

> Отдельной CASE-формулы для имени источника больше нет — оно приходит
> готовым из `source_name`.  Если в дашборде увидел подпись вида
> «Поиск: код 621» — это значит, что `id=621` пока отсутствует в
> `dicts/search_engine_roots.csv`; добавь строку в CSV и дождись
> следующего прогона функции.

## 4. Датасет `ds_touchpoints`

**Источник:** SQL-подзапрос.

```sql
SELECT
    toDate(history.UTCStartTime[-1]) AS conversion_date,
    length(history.SourceCode)       AS touchpoints
FROM metrika.visits_combined
WHERE Conversions > 0
```

### Поля

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Дата конверсии | `conversion_date` | Дата | Нет | Измерение |
| Число касаний | `touchpoints` | Целое число | Среднее | Показатель |

---

## 5. Датасет `ds_chains`

**Источник:** SQL-подзапрос.

```sql
SELECT
    history.SourceCode[i]   AS from_channel,
    history.SourceCode[i+1] AS to_channel,
    i                       AS step,
    count()                 AS visits,
    sum(Conversions)        AS conversions
FROM (
    SELECT
        history.SourceCode,
        Conversions,
        arrayJoin(range(1, length(history.SourceCode))) AS i
    FROM metrika.visits_combined
    WHERE length(history.SourceCode) >= 2
) AS expanded
GROUP BY from_channel, to_channel, step
HAVING visits >= 5
ORDER BY step, visits DESC
```

### Поля

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Откуда | `from_channel` | Строка | Нет | Измерение |
| Куда | `to_channel` | Строка | Нет | Измерение |
| Шаг | `step` | Целое число | Нет | Измерение |
| Визиты цепочки | `visits` | Целое число | Сумма | Показатель |
| Конверсии цепочки | `conversions` | Дробное число | Сумма | Показатель |

## 5.5 Датасет `ds_transitions`

**Источник:** представление `v_source_transitions` (см.
`sql/01_schema.sql`).  View резолвит оба конца перехода к
человекочитаемым именам через `dict_*` словари — JOIN'ов в DataLens
делать **не нужно**.

### Поля источника

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Дата | `start_date` | Дата | Нет | Измерение |
| Откуда (код) | `prev_source_code` | Строка | Нет | Измерение |
| Куда (код) | `next_source_code` | Строка | Нет | Измерение |
| Откуда | `prev_source_name` | Строка | Нет | Измерение |
| Куда | `next_source_name` | Строка | Нет | Измерение |
| Переходы | `transitions` | Дробное число | Сумма | Показатель |
| Конверсии через переход | `converting_chains` | Дробное число | Сумма | Показатель |

Поля `Откуда (код)` / `Куда (код)` оставлены для отладки и группировок
по сырым кодам — в дашбордах по умолчанию используй `Откуда` / `Куда`.

## 5.6 Датасет `ds_assisted`

**Источник:** представление `v_assisted_long` (см. `sql/01_schema.sql`).

DataLens стакает несколько метрик на Y по умолчанию, а сплит
`Measure Names` работает не во всех билдах UI.  Поэтому прямые и
ассоциированные конверсии уложены на стороне CH в long-формат —
отдельные строки с колонкой `metric_type`, — и в DataLens это
обычные две категории.

### Поля источника

| Название | Источник | Тип | Агрегация | Роль |
|----------|----------|-----|-----------|------|
| Источник | `source_name` | Строка | Нет | Измерение |
| Тип конверсии | `metric_type` | Строка | Нет | Измерение |
| Дата | `start_date` | Дата | Нет | Измерение |
| Конверсии | `value` | Дробное число | Сумма | Показатель |
| Доход | `value_money` | Дробное число | Сумма | Показатель |

### Вычисляемые поля

| Название | Формула | Тип | Роль |
|----------|---------|-----|------|
| Ранг источника (assisted) | `RANK_DENSE(SUM([Конверсии]) AMONG [Источник])` | Целое число | Показатель |

## 6. Палитра моделей

В каждом чарте, где модель участвует в цвете/легенде, в секции
**Цвета** → **Ручная настройка** выставить:

| Модель | Hex |
|--------|-----|
| Первый клик | `#4E79A7` |
| Последний клик | `#E15759` |
| Последний значимый клик | `#F28E2B` |
| Линейная | `#59A14F` |
| Затухающая | `#B07AA1` |

Для источников — авто-палитра, но `Прямые заходы` вручную в
серый `#9C9C9C`.

## 7. Чарты

### `kpi_revenue` — Атрибутированный доход

- Тип: **Индикатор**
- Датасет: `ds_attribution`
- Показатель: `Доход`
- Фильтры: `Название модели атрибуции = Линейная`
- Подзаголовок: «Атрибутированный доход · Линейная»
- Формат: `₽`, разделитель тысяч, без дробной части

### `kpi_conversions` — Атрибутированные конверсии

- Тип: **Индикатор**
- Датасет: `ds_attribution`
- Показатель: `Число конверсий`
- Фильтры: `Название модели атрибуции = Линейная`
- Подзаголовок: «Конверсии · Линейная»
- Формат: целое число, разделитель тысяч

### `kpi_touchpoints` — Среднее число касаний до конверсии

- Тип: **Индикатор**
- Датасет: `ds_touchpoints`
- Показатель: `Число касаний`
- Подзаголовок: «Среднее число касаний до конверсии»
- Формат: `0.0`

### `ch_model_mix` — распределение источников по моделям

- Тип: **Столбчатая диаграмма нормированная** (100% stacked)
- Датасет: `ds_attribution`
- X: `Название модели атрибуции`
- Y: `Число конверсий`
- Цвета: `Название источника атрибуции`
- Сортировка: `Число конверсий` по убыванию
- Фильтры: `Ранг источника <= 10`
- Название: «Распределение источников по моделям атрибуции»
- Подзаголовок: «Как по-разному модели атрибутируют каналы»

### `ch_time_series` — конверсии топ-источников во времени

- Тип: **Линейная диаграмма**
- Датасет: `ds_attribution`
- X: `Дата`
- Y: `Число конверсий`
- Цвета: `Название источника атрибуции`
- Сортировка: по `Дата` по возрастанию (иначе точки внутри линии
  идут в порядке убывания метрики — линии зигзагом)
- Фильтры: `Ранг источника <= 10`
- Название: «Конверсии топ-источников во времени»
- Подзаголовок: «Переключите модель атрибуции, чтобы увидеть разницу»
- Ось Y: линейная
- Сглаживание: выкл

### `ch_channel_grouped` — топ-10 источников × 5 моделей

- Тип: **Столбчатая диаграмма**
- Датасет: `ds_attribution`
- X: `Название источника атрибуции`, **`Название модели атрибуции`**
  (в таком порядке — оба в секции X; внешняя группировка по источнику,
  внутренняя по модели, столбцы стоят рядом без стакинга)
- Y: `Число конверсий`
- Цвета: `Название модели атрибуции` (палитра из §6)
- Сортировка: `Число конверсий` по убыванию
- Фильтры: `Ранг источника <= 10`
- Название: «Топ источников: расхождения между моделями»

### `ch_assisted` — прямые vs ассоциированные конверсии

- Тип: **Столбчатая диаграмма**
- Датасет: `ds_assisted` (см. §5.6 — long-формат, обходит стакинг)
- X: `Источник`, `Тип конверсии` (в таком порядке, оба в секции X — внешняя группировка по источнику, внутренняя по типу)
- Y: `Конверсии`
- Цвета: `Тип конверсии`
- Фильтры: `Ранг источника (assisted) <= 10`
- Сортировка: `Конверсии` по убыванию
- Название: «Прямые vs ассоциированные конверсии»
- Подзаголовок: «Для каждого канала — прямой (last-touch) и ассоциированный объём»

### `ch_transitions_matrix` — матрица переходов «откуда → куда»

Аналог Sankey через **сводную таблицу** с условным форматированием
ячеек (нативного heatmap-типа в DataLens нет, но у pivot с
background-цветом выходит тот же визуальный эффект: темнее клетка —
чаще переход).

- Тип: **Сводная таблица**
- Датасет: `ds_transitions`
- Строки: `Откуда`
- Столбцы: `Куда`
- Показатели: `Переходы` (Сумма)
- Фильтры: топ-N реальных переходов (не top-N по осям независимо —
  так матрица не дырявая). В `ds_transitions` создать calc-поле:
  - `Ранг перехода = RANK_DENSE(SUM([Переходы]) AMONG [Откуда], [Куда])`
  - В чарте: `Ранг перехода <= 100`.
- Сортировка: `Переходы` по убыванию
- Итоги: по строкам и по столбцам — **включены** (сразу видно суммарные in/out по источнику)
- **Условное форматирование:** в настройках показателя `Переходы` →
  «Цветовое кодирование» → фон по значению, градиент
  `#FFFBEA → #E15759` (светло-жёлтый → красный).
- Формат показателя: целое число, разделитель тысяч
- Название: «Матрица переходов между источниками»
- Подзаголовок: «Темнее клетка — чаще переход»

### `ch_pivot` — сводная таблица источник × модель

- Тип: **Сводная таблица**
- Датасет: `ds_attribution`
- Строки: `Название источника атрибуции`
- Столбцы: `Название модели атрибуции`
- Показатели: `Число визитов`, `Число конверсий`, `Доход`, `Доход на конверсию`
- Сортировка: `Число конверсий` по убыванию
- Фильтры: `Ранг источника <= 10`
- Итоги: по строкам и по столбцам — включены
- Условное форматирование: цветовая заливка по `Число конверсий` внутри столбца
- Название: «Источник × модель: все метрики»

## 8. Раскладка дашборда

Название дашборда: `Атрибуция Метрики — Витрина`.

**Сетка 24 колонки, высота строки = 4 юнита.**

| Ряд | Чарты | Раскладка (x, y, w, h) |
|-----|-------|------------------------|
| 1 (KPI) | `kpi_revenue`, `kpi_conversions`, `kpi_touchpoints` | (0,0,8,4) (8,0,8,4) (16,0,8,4) |
| 2 | `ch_model_mix` (слева), `ch_time_series` (справа) | (0,4,12,8) (12,4,12,8) |
| 3 | `ch_channel_grouped` (во всю ширину) | (0,12,24,8) |
| 4 | `ch_assisted` (во всю ширину) | (0,20,24,10) |
| 5 | `ch_transitions_matrix` (во всю ширину, высокая) | (0,30,24,14) |
| 6 | `ch_pivot` (во всю ширину, высокая) | (0,44,24,16) |

## 9. Глобальные селекторы

На каждый селектор:
1. **Добавить** → **Селектор** на дашборд.
2. Настроить источник значений (датасет + поле).
3. В **Связях** дашборда привязать селектор к чартам, указав
   поле-фильтр для каждого.

### Селектор «Период»

- Тип: диапазон дат.
- Источник значений: датасет `ds_attribution`, поле `Дата`.
- Значение по умолчанию: «последние 30 дней».
- Связи:
  - `kpi_revenue`, `kpi_conversions`, `ch_model_mix`, `ch_time_series`,
    `ch_channel_grouped`, `ch_pivot` → поле `Дата` (из `ds_attribution`).
  - `kpi_touchpoints` → поле `Дата конверсии` (из `ds_touchpoints`).

### Селектор «Модель»

- Тип: выпадающий список (один вариант).
- Источник значений: `ds_attribution`, поле `Название модели атрибуции`.
- Значение по умолчанию: `Линейная`.
- Связи: `kpi_revenue`, `kpi_conversions`, `ch_pivot`, `ch_channel_grouped`,
  `ch_time_series` → поле `Название модели атрибуции`.
  `ch_model_mix` — **не связывать** (он всегда показывает все 4 модели).

### Селектор «Источник»

- Тип: выпадающий список (несколько вариантов).
- Источник значений: `ds_attribution`, поле `Название источника атрибуции`.
- Значение по умолчанию: пусто (все источники).
- Связи: все чарты на `ds_attribution` → поле `Название источника атрибуции`.

## 10. Экспорт и коммит

1. В воркбуке → меню **⋯** → **Экспортировать**.
2. Скачанный файл положи как `datalens/dashboard.json` в корне репо.
3. Коммить:
   ```bash
   git add datalens/dashboard.json
   git commit -m "datalens: add exported dashboard.json"
   ```

---

## 11. Проверка: импорт в другой каталог

1. `terraform apply` в другом каталоге (новый `clickhouse_cluster_id`).
2. Открыть <https://datalens.yandex.cloud/collections> →
   **Создать → Воркбук** → «Импорт из файла» → `datalens/dashboard.json`.
3. На шаге привязки подключения — выбрать новый кластер из списка.
4. Открыть дашборд — все чарты должны работать без ошибок.

Если хоть один чарт красный — импорт сломан, заводим issue.
